# 2026-10-20 — Runtime configuration, HTTP and form foundations

Implemented the application boundary for later API integration. Demo screens still use their existing in-memory state; this step adds no backend requests, authentication, refresh flow, global error toast or automatic retry.

## Public runtime configuration

- `window.__BOILERATE_UI__` is untrusted until `readRuntimeConfig()` validates it before bootstrap. An absent object or omitted API setting uses `/api`; invalid supplied values fail startup rather than silently falling back.
- Supported settings are `apiBaseUrl` and optional `primeUiLicense`. The returned value is frozen and supplied through `RUNTIME_CONFIG` using `provideRuntimeConfig()`.
- API prefixes support a root-relative path or HTTP(S) URL. Credentials, queries, fragments and traversal paths are rejected. Validation errors identify the setting without printing its value or the configuration object.
- `scripts/runtime-config.mjs` uses Node's environment-file loader for ignored `.env.local`; existing shell/CI environment values take precedence, including an explicitly empty license. It emits the one existing ignored `public/runtime-config.js` file.
- `.env.example` contains `/api` and an empty optional license placeholder. Public runtime configuration is readable by the browser and must never contain backend credentials or access tokens.

## HTTP and forms

- `apiUrl()` joins a relative resource to the configured API prefix. Absolute resources, traversal and embedded query/fragment syntax are rejected; query parameters belong in `HttpParams`.
- `apiErrorInterceptor` applies only to the configured API origin/path. Asset and other-origin responses retain their original errors. A caller with a special response contract can set `SKIP_API_ERROR_NORMALIZATION` in its `HttpContext`.
- `ApiError` carries a safe Vietnamese message, HTTP status, kind, optional bounded code/trace ID and field errors. The normalizer accepts `unknown`, flattened ASP.NET ProblemDetails and explicit `extensions`; it tolerates empty, malformed and non-JSON bodies. It does not retain raw server details, request URLs, response headers or server stack traces.
- `PaginationResponse<T>` mirrors the backend `data`, `currentPage`, `totalPages`, `totalCount`, `pageSize`, `hasPreviousPage`, `hasNextPage` contract. Request page numbers remain one-based; feature adapters own UI index conversion.
- `applyServerErrors()` accepts typed reactive forms through their `AbstractControl` contract. PascalCase properties, nested groups, array indexes and explicit field aliases map to known controls. It replaces only old `server` errors, preserves client validator errors and returns unknown fields for a form summary. It does not import core or feature code.
